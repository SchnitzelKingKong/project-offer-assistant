# 0004 - PII sanitization in the pipeline, never in the app

- Status: Accepted
- Date: 2026-08-18

## Context

Real offer documents contain personal data (names, addresses, phone
numbers). The repository is public and the app may run on shared
infrastructure. The question is where in the system PII must be removed.

## Decision

**Redaction happens once, in the pipeline, before anything is indexed.**
Notebook 02 runs the PII sanitizer (`scripts/sanitizer.py`) on the raw
texts; only the redacted texts (`data/redacted/`) feed extraction and
indexing. The app never sees unredacted content and performs no redaction
of its own.

Committed data is additionally protected by construction:

- `data/raw/` (unredacted) and `data/db/` (index) are git-ignored — real
  customer data never enters version control.
- `data/redacted/` and `data/extracted/` contain only fictitious sample
  data generated by `source/offers/`.

## Consequences

- One deterministic, testable sanitization step instead of scattered
  runtime checks; the index is clean by construction.
- The privacy boundary is the pipeline input, not the app — the app can
  be run anywhere without additional data-protection measures.
- If the sanitizer misses a pattern, it is fixed once in the pipeline and
  the index is rebuilt — no runtime patching.
